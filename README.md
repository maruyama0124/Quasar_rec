# Quasar Rec — 謎解きレクリエーションアプリ

サークル合宿（約50名参加）で使う、**スマートフォン向け謎解きゲーム** のWebアプリです。
宿の中を歩き回って主催者を探し、クイズ・撮影・暗号入力を繰り返して7枚のスクショを集め、
最後に並べ替えて1つのクイズを完成させる——というリアル連動型の体験を提供します。

> 並べ替えや最終回答の正誤判定は **アプリ内では行いません**。主催者が目視で確認する運用です。

---

## ゲームの流れ

```
[1] チーム選択
 ↓
[2] 宿の中で主催者を探す（アプリ外のリアル行動）
 ↓
[3] 主催者のクイズに正解 → 一緒に記念撮影（手のポーズが次のヒント）
 ↓
[4] ヒントをもとに宿のどこかの封筒を探す（アプリ外）
 ↓
[5] 記念写真をアプリにアップロード（思い出 & 証拠）
 ↓
[6] 封筒の暗号をアプリに入力 → 正しければスクショ1枚を獲得
 ↓
[7] [2]〜[6] を繰り返して全7枚のスクショを集める
 ↓
[8] 7枚をドラッグ&ドロップで正しい順番に並べ替え → 1つのクイズが完成
 ↓
[9] そのクイズの答えを主催者に口頭で伝える → クリア
```

---

## 主な機能

- **チーム選択画面** — 9チームから選択。進捗があるチームには「続きから」バッジを表示
- **メイン画面（暗号入力 / スクショ収集）**
  - 暗号入力 → 正規化（全角→半角、英字→大文字、ひらがな→カタカナ）して照合
  - 一致するとスクショ画像を獲得（「獲得 3 / 7」のように進捗表示）
  - 記念写真をカメラ/ライブラリから撮影 → クライアント側でリサイズ＋JPEG圧縮して保存
- **並べ替え画面** — 7枚のスクショをドラッグ&ドロップで並べ替え（touchイベントで自前実装）
- **進捗の永続化** — `window.storage` に保存し、リロード・ブラウザ再起動後も再開可能
- サーバーレス・クライアント完結のため、同時接続人数の制約なし

## 技術スタック

| 項目 | 採用 |
|------|------|
| フレームワーク | React 19 |
| ビルドツール | Vite 7 |
| 状態管理 | React `useState` / `useEffect` |
| 進捗永続化 | `window.storage` API |
| 画像 | Base64 データURL埋め込み（外部サーバー不要） |
| 対象デバイス | スマートフォン（iOS Safari 16+ / Android Chrome、375〜430px幅が主対象） |

スタイリングはダークネイビー＋ゴールドの「謎解き感」を演出する独自スタイルで実装しています。

## セットアップ

```bash
# 依存パッケージのインストール
npm install

# 開発サーバー起動
npm run dev

# 本番ビルド
npm run build

# ビルド結果のプレビュー
npm run preview
```

### デプロイ

`vite.config.js` で配信先に応じて `base` を切り替えています。

- **Vercel など（ルート配信）** — そのままビルド（`base: '/'`）
- **GitHub Pages（サブパス配信）** — 環境変数 `GITHUB_PAGES` を設定してビルド（`base: '/Quasar_rec/'`）

  ```bash
  GITHUB_PAGES=1 npm run build
  ```

## ゲーム内容の差し替え（主催者向け）

暗号とスクショ画像は `App.jsx` 内の `CODE_MAP` で管理しています。

```javascript
const CODE_MAP = {
  "サクラ":   { id: 1, image: "data:image/jpeg;base64,/9j/4AAQ..." },
  "フジサン": { id: 2, image: "data:image/jpeg;base64,/9j/4AAQ..." },
  // ... 全7つ分
};
```

- **キーは「大文字・カタカナ」で記述** してください。アプリ側が入力を同形式に正規化して照合するため、
  ユーザーが「さくら」「sakura」「SAKURA」のどれを入力しても `"サクラ"` にマッチします。
- 画像は横幅800px以下・JPEG品質80%程度にリサイズしてからBase64（Data URI形式）に変換するのを推奨します。
- チーム名は `App.jsx` の `TEAMS` 配列で定義しています。

詳しい手順・画面仕様・データ構造は [`specification.md`](./specification.md) を参照してください。
